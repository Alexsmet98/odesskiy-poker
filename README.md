# Одесский покер

Играбельная веб-версия одесского покера на четверых. На главной странице меню из трёх пунктов:

1. **Создать лобби** — хозяин получает четырёхбуквенный код и ссылку, зовёт друзей;
2. **Присоединиться к лобби** — имя и код (или переход по ссылке `/lobby/КОД`);
3. **Играть с ботами** — один живой игрок против трёх ботов (`/bots`).

Атмосфера — подвальный бар у порта: тусклая лампа над столом, дым, зелёное сукно.

Правила реализованы по спецификации заказчика: торговля с правилом «не сходимся»,
ход в масть, оба джокера со всеми режимами, тёмные, наборы, сливы и полное расписание
партии из 43 строк протокола.

## Что внутри

- `src/lib/game/` — движок правил на чистом TypeScript, без зависимости от UI:
  - `cards.ts` — колода 36 карт + 2 джокера, старшинство, сортировка руки;
  - `schedule.ts` — расписание партии: 36 игровых раздач и 7 строк премии;
  - `rules.ts` — легальность заказов, требование масти, разбор взятки со всеми режимами джокера;
  - `scoring.ts` — очки за раздачу, премия, зачёт наборов и сливов, таблица протокола;
  - `engine.ts` — состояние партии и переходы (`applyAction`);
  - `ai.ts` — боты: выбирают ход только из разрешённых правилами.
- `src/lib/net/` — сетевой режим:
  - `lobby.ts` — `LobbyManager`: лобби, места, боты на пустых местах, таймеры ботов, авторитетная партия на сервере;
  - `view.ts` — маскирование состояния: чужие карты в рассылку не попадают;
  - `protocol.ts`, `client.ts`, `session.ts` — типы, HTTP-клиент, сессия игрока (`sessionStorage`, своя на каждую вкладку).
- `src/app/api/lobbies/` — HTTP API: создание, вход, старт, ход, выход и поток событий (SSE).
- `src/components/menu/` — главное меню и экран лобби (комната ожидания).
- `src/components/game/` — стол (общий для обоих режимов), руки, джокер-диалог, протокол, лог за столом.
- `src/lib/game/__tests__/` — юнит-тесты Vitest: торговля, взятки, все режимы джокера, подсчёт очков.

## Правила кратко

- 4 игрока, колода 38 карт (36 + 2 джокера: красный слабее чёрного), козырной масти нет, сдача по кругу.
- Торговля: первым торгуется игрок слева от сдающего, сдающий — последним и не может
  замкнуть сумму заказов на числе карт на руках («не сходимся»).
- Взятку забирает старшая карта масти хода. Джокер игнорирует масть: в ответ его кладут
  наисильнейшим козырем либо самой младшей картой. Заход джокером — четыре режима: «старший»
  и «младший» (взятка ваша, даже против туза и шестёрки; красный заход бьёт чёрный джокер
  «старшим козырем», заход чёрным красный не перебивает) и два слива.
  На «джокере старшем» у кого есть названная масть, тот обязан положить самую старшую
  её карту (десятку при тузе на руках скинуть нельзя). Нет масти — любую карту, джокера можно всегда.
- Слив «заберёт старшая» / «заберёт младшая»: остальные обязаны выложить именно старшую / младшую
  карту названной масти из своей руки (нет масти — любую, джокера можно всегда). На сливе
  «заберёт старшая» и «заберёт младшая» джокер любого цвета, объявленный старшим козырем,
  забирает взятку. Без такого джокера на «заберёт младшая» побеждает самая младшая карта масти:
  шестёрка бьёт короля. Джокер, положенный «самой младшей картой», взятку не берёт.
- Очки: точный заказ — 10 за взятку, выполненный пас — 5, перебор — 1 за каждую взятку, которую взял игрок (заказал 2, взял 4 — +4),
  недобор — −10 за каждую недобранную взятку.
- Премия («Пр») — тому, кто в каждой раздаче блока взял ровно свой заказ: очки за раздачу
  с самым большим заказом блока, удвоенные целиком (заказ 4 → +80, блок из пасов → +10).
  В протоколе у ближайшего блока видно, кто ещё в гонке за премией.
- Тёмные идут с удвоенными очками, а премия за них удваивается ещё раз (заказ 4 → 4×10×2 = 80, премия 160).
- Хозяин сетевого лобби может править записи в протоколе (кнопка «Править»); очки и премии пересчитываются.
- В журнале и по кнопке «Последняя взятка» видна только последняя взятка.
- Наборы и сливы очки сразу не дают: в конце партии ОН − ОС = Сум НС, Очки НС = Сум НС × 20,
  Итого = очки за раздачи и премии + Очки НС.

## Игра с друзьями из других мест

Лобби живёт на сервере, поэтому ссылка вида `http://127.0.0.1:43711/lobby/КОД` работает только у вас.
Чтобы друзья могли зайти, приложение должно быть доступно по публичному адресу — ссылка
«Скопировать ссылку» берёт тот адрес, под которым открыта страница.

- **Временно, с вашего компьютера.** Соберите и запустите production-версию и откройте её через туннель:

  ```bash
  npm run build && npm start -- --port 43712
  cloudflared tunnel --url http://127.0.0.1:43712   # выдаст https://….trycloudflare.com
  ```

  Откройте выданный https-адрес сами и создавайте лобби оттуда — ссылка для друзей будет публичной.
  Адрес живёт, пока работает туннель.

- **Постоянно.** Подойдёт любой хостинг, где запускается обычный Node-процесс (Render, Railway,
  Fly.io, VPS): в репозитории есть `Dockerfile`, порт 3000. Нужен **один постоянно работающий процесс**;
  serverless-платформы (например, Vercel) не подходят — состояние лобби хранится в памяти процесса.
- Основной канал связи — SSE, а если прокси или туннель его буферизуют (так делают бесплатные туннели
  Cloudflare), клиент через пару секунд сам переходит на long-poll (`/api/lobbies/:code/poll`).

## Сетевая игра

- Партия живёт на сервере в памяти процесса: клиент шлёт только свои действия
  (`POST /api/lobbies/:code/action`), а состояние получает потоком SSE
  (`GET /api/lobbies/:code/events`). Каждому игроку приходит своя версия состояния
  без чужих карт.
- Хозяин может начать партию, не дожидаясь всех: пустые места займут боты.
- Если закрыть вкладку, в той же вкладке партия подхватится после перезагрузки.
  Ход отключившегося человека ждёт его возвращения; кнопка «Выйти» отдаёт место боту.
- Ограничения: лобби хранятся в памяти одного процесса (перезапуск сервера их обнуляет,
  несколько реплик не поддерживаются), простаивающие лобби удаляются через 6 часов.

Полная спецификация правил лежит в контексте проекта (`docs/game-rules.md`).
